# DynamiQ

Manufacturing scheduling dashboard using React, FastAPI, OR-Tools CP-SAT, and SQLite.

## Deploy with Docker Compose

The production Compose setup serves the dashboard through Nginx and stores application data in a persistent SQLite database volume. No Docker MongoDB service, Atlas account, or separately installed database server is required.

1. Install Docker Engine with the Docker Compose plugin on the deployment host.
2. Create the repository-root `.env` file from `.env.example` and set a unique `BASIC_AUTH_USER` and a strong `BASIC_AUTH_PASSWORD`.
3. Build and start the services from the repository root:

   ```sh
   docker compose up --build -d
   ```

4. Verify the deployment at [http://127.0.0.1:8080](http://127.0.0.1:8080). Nginx prompts for the shared dashboard credentials and protects both the UI and API.
5. Check API and database health at [http://127.0.0.1:8080/api/health](http://127.0.0.1:8080/api/health).

The API creates its SQLite tables and indexes at startup. Resources, tasks, archived tasks, and the latest schedule are stored in the database. In Docker Compose, the database file is persisted in the `app_data` Docker volume. Back up this volume as part of deployment operations.

For local development, the database defaults to `backend/data/dynamiq.sqlite3`.

The web port binds to loopback and is not exposed directly to external networks. Configure a TLS reverse proxy on the host to forward requests to `127.0.0.1:8080` before making the site public. Basic Auth credentials must be transmitted over HTTPS.

## Deploy to Render

The repository-root `render.yaml` defines a public dashboard and a private API service. In Render, create a new Blueprint, connect this repository, and deploy the `render.yaml` configuration. The dashboard uses HTTP Basic Authentication (`dynamiq` and a password generated by Render); find the generated password in the dashboard service's environment settings.

The API uses SQLite on a 1 GB persistent disk mounted at `/data`. Render persistent disks require a paid service plan, so the API's `starter` plan has a cost. The dashboard uses Render's free web-service plan and may spin down when idle. Keep both services in the same region. The API is private and is reachable only through the dashboard's internal proxy. `/healthz` is an unauthenticated health-check endpoint; application pages and API routes require authentication.

Do not remove the API disk or change `SQLITE_PATH` if you need to preserve data between deploys. SQLite with a persistent disk is intended for this single-instance deployment; the API cannot be horizontally scaled while using the disk. Render filesystems outside `/data` are ephemeral.

## Local Development

Run the backend and frontend in separate terminals from the repository root.

### Prerequisites

- Python installed and available in PATH.
- Node.js and npm installed, or the Node.js Windows ZIP distribution extracted into the repository root.
- Git, if you are cloning the repository.

### 1. Start the Backend

Open the first terminal in the repository root and run:

```powershell
cd backend
python -m pip install -r requirements.txt
python -m uvicorn api:app --reload --host 127.0.0.1 --port 8000
```

The FastAPI backend will be available at:

- API: `http://127.0.0.1:8000`
- API documentation: `http://127.0.0.1:8000/docs`

Keep this terminal running.

### 2. Start the Frontend

Open a **second terminal** in the repository root.

#### Option A: Node.js installed and available in PATH

Run the following commands:

```powershell
cd frontend
npm ci
npm run dev
```

#### Option B: Node.js extracted as a ZIP folder in the repository root (Windows)

If Node.js is extracted into the `node-v24.22.0-win-x64` folder in the repository root, use the following commands in PowerShell:

```powershell
$env:Path = "$(Resolve-Path .\node-v24.22.0-win-x64);$env:Path"
cd frontend
npm.cmd ci
npm.cmd run dev
```

If your terminal is already inside the `frontend` directory, run:

```powershell
$env:Path = "$(Resolve-Path ..\node-v24.22.0-win-x64);$env:Path"
npm.cmd ci
npm.cmd run dev
```

The PATH change applies only to the current terminal session. Keep the terminal open while running the frontend.

Using `npm.cmd` avoids PowerShell's script-execution restriction on `npm.ps1`.

If `npm ci` fails with an `EPERM` error, close any running frontend development servers and retry the command. If the project does not contain a `package-lock.json` file, use `npm.cmd install` instead.

After the frontend starts, open the local URL printed in the terminal, typically:

`http://localhost:5173`

Keep both the backend and frontend terminals running during development.

## Database

DynamiQ uses SQLite for local development and Docker deployments.

- Local database: `backend/data/dynamiq.sqlite3`
- Docker database: persisted in the `app_data` volume.
- Database tables and indexes are initialized by the API at startup.

No separate database server is required.

## Troubleshooting

**`npm` is not recognized**

Use Option B in the frontend setup instructions, or install Node.js and ensure it is added to PATH.

**PowerShell blocks `npm.ps1`**

Use `npm.cmd` instead of `npm`.

**`node` is not recognized during dependency installation**

Ensure the Node.js directory has been added to the current terminal's PATH before running `npm.cmd ci`.

**Dependency installation fails with `EPERM`**

Close running Node.js processes that may be using `frontend/node_modules`, then retry `npm.cmd ci`.

**Frontend cannot connect to the backend**

Ensure the FastAPI backend is running at `http://127.0.0.1:8000` and verify the frontend's API configuration and backend CORS settings.

**Docker deployment fails**

Check that Docker Engine and the Docker Compose plugin are running, that the repository-root `.env` file is configured, and that the required ports are available.
